# 管理后台、权限与安全设计

上级文档：[开发总览](README.md)。后台目标是方便站主持续维护内容，首期只有一个管理员。

## 1. 后台工作流

| 操作 | 步骤与反馈 |
| --- | --- |
| 编辑资料 | 读取资料及 version → 编辑 → 校验 → 保存 → 提示已公开生效 |
| 新建内容 | 选择类型 → 填标题/slug/摘要 → 保存草稿 → 上传并关联图片 → 预览 |
| 发布 | 明确点击发布 → 后端发布级校验 → 返回新版本 → 提供公开链接 |
| 更新已发布内容 | 页面提示保存立即公开 → 确认保存 → 刷新预览和公开查询 |
| 下线/归档 | 显示影响 → 确认 → 公开 API 不再返回该内容及仅该内容引用的图片 |
| 永久删除 | 仅 draft/archived → 确认标题与不可直接恢复 → 删除；媒体留库 |
| 管理媒体 | 上传 → 私有预览 → 插入内容 → 显示引用数；未使用图片可手动删除 |
| 修改密码 | 输入当前密码和新密码 → 校验 → 撤销所有会话 → 重新登录 |

分类和标签以类型分组，不提供跨类型移动；后台内容列表显示状态、标题、更新时间和公开链接（仅已发布）。当前 UI 的仪表盘提供第一方流量统计；访问明细及 IP/区域封锁也纳入设计。`/admin/dashboard` 只返回内容计数和近期编辑，流量由 `/admin/analytics` 提供。统计口径、IP 可见范围和封锁执行见 [11](11-analytics-and-access-control.md)。

## 2. 管理员初始化与密码

管理员通过服务器 CLI 创建，不提供公开注册、默认账号密码或网络初始化接口。创建时输入真实用户名和新密码，推荐密码管理器生成，首期要求 12–128 字符，允许空格，不截断或静默裁剪密码。账号统一小写；登录失败统一提示“用户名或密码错误”。

密码使用 Argon2id、每个密码独立随机盐，保存标准 PHC 字符串。初始可采用 64 MiB 内存、3 次迭代、并行度 1，并在目标服务器测量登录耗时和内存后调整；限制并发密码计算，防止内存耗尽。依据为 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。忘记密码使用服务器受限 CLI 重设，首期不做邮箱找回。

## 3. Session 与 Cookie

登录成功用密码学安全随机数生成至少 256 bit token，返回 HttpOnly Cookie；数据库只保存 token SHA-256。每次重新登录创建新 token，避免固定会话。退出删除当前会话，修改/重设密码删除全部会话。

生产 Cookie：`__Host-admin_session`，`Secure; HttpOnly; SameSite=Lax; Path=/`，不设置 Domain。Path=/ 使媒体请求也能携带会话；公开接口不会因此获得管理权限。开发 HTTP 使用单独的 `admin_session_dev` 名称、显式关闭 Secure，只允许 development 环境，生产启动拒绝该配置。

闲置 12 小时到期，绝对最长 7 天，取更早者；GET /auth/session 可返回当前到期时间和会话 CSRF token。服务端到期检查为准，Cookie Max-Age 与当前有效期一致。禁止在 localStorage、URL 或日志保存 token。会话策略参考 [OWASP Session 管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

## 4. CSRF、来源检查与跨域

使用与 Session 关联的随机 CSRF token，通过登录响应或同源 `/auth/session` 响应返回，前端写请求放 `X-CSRF-Token`；后端固定时间比较。管理写请求还要求 Origin 完全等于 PUBLIC_ORIGIN；缺失、null 或不匹配拒绝，不信任 Host 自动推断可信来源。

登录尚无 Session token，采用严格 Origin + application/json + 登录限流保护；不接受表单 Content-Type。上传为 multipart 但仍要求 CSRF token 和 Origin。GET 不执行发布、删除、退出或业务写入。SameSite 是额外保护，不能替代上述校验，参考 [OWASP CSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。

开发走 Vite 代理，生产走 Caddy，同源部署不需要允许任意 CORS。禁止 `Access-Control-Allow-Origin: *` 搭配带凭据访问。公开 API 也不主动授予跨域读取权限。

## 5. 输入与渲染

前后端都做字段和 URL 校验，后端拒绝未知字段；公开资料 Markdown 不允许图片，内容图片只能使用已登记 media ID。正文渲染禁用原生 HTML/MDX，禁止 javascript/data 等危险链接。资料链接只允许 https/mailto，项目外链只允许 https。

后台预览使用相同渲染链，避免预览安全但公开站危险。代码块只展示文本。API 使用 SQL 参数绑定，不允许用户自定义 SQL 排序。Caddy/前端采用 CSP 约束脚本、连接与图片来源，`frame-ancestors 'none'` 防止后台被嵌套；实际策略须与构建产物联调，不能为省事开放任意脚本来源。

## 6. 上传、隐私与可见性

仅允许 JPEG/PNG/WebP，文件签名、体积、像素和解码资源都检查，重编码去掉定位元数据；不接收 SVG、HTML、可执行文件、远程 URL 抓取或压缩包。详细处理见后端文档。

媒体卷不可由 Caddy 直接公开，读取必须经 Rust 检查当前引用状态。管理员知道媒体 ID 也不能绕过 API 权限；草稿图片 URL 不构成授权。上传但未保存的图片仅管理员可读。

下线会使后续访问失败，无法抹去已经下载、截图或被第三方保存的信息。生活发布前提示检查面孔、定位、票据等真实信息；精确地点不作为必填项。生产不在日志记录正文、密码、Cookie、CSRF token。

## 7. 限流与资源限制

单实例初始登录限流：每个可信客户端 IP 每 15 分钟最多 10 次失败，账号每 15 分钟最多 20 次失败，返回 429 与 Retry-After。避免无限期账号锁定；成功登录可清理该来源的失败计数。代理必须移除伪造的客户端 IP 头，Axum 只信任 Caddy。

首期可用进程内限流，重启会清零，扩大部署时需迁到共享存储。上传每会话每分钟最多 20 次，受限并发解码；公开列表限制 page_size/q 长度，数据库连接池与超时有明确上限。部署时为数据库、后端与日志预留磁盘，剩余空间不足时应拒绝新上传并记录可排查的错误。

## 8. 权限验证清单

| 场景 | 预期 |
| --- | --- |
| 未登录直接调用管理 GET/写接口 | 401，数据库无变化 |
| 登录后缺 token 或来源不合法 | 403，数据库无变化 |
| 公开请求草稿 slug、归档 slug、私有图片 ID | 404，不泄露标题或真实文件路径 |
| 下线后只属于该内容的图片请求 | 404；仍被其他已发布内容引用的图片继续可读 |
| 两个标签页提交相同 version | 只有一份写成功，另一份 409 |
| 删除被草稿/归档/头像引用的媒体 | 409，引用与文件保留 |
| 修改密码后使用旧 Session | 401 |
| 危险 Markdown、SVG、超大/解码炸弹图片 | 拒绝或安全显示，不执行脚本、不无界消耗资源 |

审计覆盖资料保存、创建/修改/发布/下线/归档/删除内容、分类标签变更、媒体删除、密码修改。运行日志与审计有保留周期，备份也包含敏感数据，应加密并限制访问。

## 9. 访问数据与规则权限

完整 IP/区域明细仅管理员可读，事件保留 60 天，聚合保留 365 天；备份同步遵守保留策略。不得信任访客提交的 IP、区域或转发头。规则创建、更新、解除和删除都要求 Session/Origin/CSRF 并写审计。封锁公共入口返回 403 ACCESS_DENIED，不返回规则目标/原因；区域未知时只匹配 IP 规则。管理、登录、健康检查豁免业务封锁但保留独立鉴权和限流，服务器 CLI 提供误封恢复能力。
