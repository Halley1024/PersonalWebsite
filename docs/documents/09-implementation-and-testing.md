# 实施计划、测试与验收

上级文档：[开发总览](README.md)。本文包含前后端和部署的整体实施目标。后端已经完成本地实现与部分验收，具体证据及未验证范围见 [后端验收记录](../../backend/docs/implementation.md)；下列整体场景不能全部当作已经通过。

## 1. 开发顺序

| 阶段 | 工作项 | 可验收产物 |
| --- | --- | --- |
| M0 基础工程 | 初始化 Vite React TS、Rust Axum；环境示例；PostgreSQL 开发容器；迁移；健康检查 | 空库迁移成功，React 请求 Rust health/API；锁文件与工具链入库 |
| M1 登录与资料 | 单管理员 CLI、Argon2id、Session、CSRF、Origin；profile/settings API 与后台表单 | 登录→保存资料→公开页面读取；密码修改后旧会话失效 |
| M2 内容与媒体 | 统一内容表、类型扩展、分类标签、版本锁、状态机；上传与引用检查 | 三类内容从草稿到公开再下线，媒体权限随引用变化 |
| M3 公开页面 | 原型组件化；首页/关于/三类列表详情；筛选搜索、分页、异常页 | 手机/桌面阅读完整，路由刷新可用，空数据可用 |
| M4 流量与访问控制 | pageview、服务端 IP/区域、7/30 天真实聚合、访问筛选、规则 CRUD 与边缘检查 | 统计口径可复算，规则真实拦截，未知区域及误封恢复可验证 |
| M5 生产与恢复 | 多阶段镜像、Caddy HTTPS、Compose、秘密、备份恢复与日志 | 空服务器部署通过，容器替换不丢数据，隔离恢复通过 |

API、数据库约束与状态机先于页面做稳定，再进行前后端联调。M1 必须建立完整权限边界，不能先把管理写接口无鉴权上线后再补。

## 2. 推荐的最小垂直切片

先实现“个人介绍”闭环：迁移出资料表 → GET /profile → 前台介绍组件 → 登录与 GET/PUT /admin/profile → 后台保存 → 前台刷新。这样可以尽早验证 Rust、数据库、React、Cookie、CSRF 和同源代理是否连通。

第二条闭环选择博客：创建草稿 → 上传封面与正文图片 → 预览 → 发布 → 公开详情 → 下线 → 验证正文和图片不可见。作品与生活在已有内容能力上增加类型字段，不复制三套鉴权和发布逻辑。

## 3. 测试层次

| 层次 | 重点 | 执行环境 |
| --- | --- | --- |
| Rust 业务单元测试 | 状态转换、slug/URL 校验、Markdown 媒体提取、版本冲突映射 | 本地与 CI |
| PostgreSQL 集成测试 | 真正的事务回滚、唯一/外键约束、并发保存、媒体引用删除竞争 | 每次独立数据库/临时卷，不用 SQLite 替代 |
| HTTP 集成测试 | Session、Origin、CSRF、公开过滤、分页、错误 envelope | 测试 Axum router + 独立数据库 |
| 前端重点组件测试 | Markdown 危险输入、API 异常、冲突提示、未保存离开 | Vitest/Testing Library 等，初始化时选择稳定版本 |
| 端到端 | 登录→编辑→上传→发布→公开读取→下线 | Playwright 或浏览器验证，覆盖关键链路 |
| 部署演练 | 空卷迁移、镜像替换持久化、HTTPS 路由、备份恢复 | 独立 Compose project |

不为简单样式和纯透传组件堆重复测试，优先验证权限、数据一致性和真实用户流程。图片处理要加入损坏文件、超尺寸和伪造扩展名输入，防止只测试正常图片。

## 4. API 与数据库检查

- 使用 OpenAPI 生成前端类型，后端 DTO/路径变更时重新生成并审查差异，文档示例也需同步。
- 对每个管理接口验证无会话、过期会话、无 CSRF、错误 Origin 四种拒绝路径，确认拒绝后数据库无业务写入。
- 对公开列表、详情、分类标签和媒体验证 draft/archived 不可见，不能只检查某一个详情接口。
- 同 version 并发更新主表、扩展、标签和图库，必须只有一个事务成功；失败不应留下部分关系。
- 同 kind slug 重复返回 409，跨 kind 允许同名；分类标签跨 kind 绑定失败。
- 删除被任何状态引用的媒体返回 409；并发删除与引用建立不能产生缺图或悬空记录。
- SQLx 若采用编译期查询宏，CI 先迁移临时数据库再 prepare/check，或提交并检查 `.sqlx` 离线元数据；禁止靠生产数据库完成编译。

## 6. 页面质量与性能目标

测试 360/768/1440px，检查导航、卡片、表格、图片和代码块，无整页水平溢出；仅代码与大表格允许局部滚动。键盘可完成登录、保存与弹窗确认；图片有 alt，表单有 label，背景动画可减弱。

初始性能预算为待验证目标：部署环境热缓存下，普通公开列表/详情 API p95 <300ms（不计图片传输）；至少以 1,000 条内容、20 并发读取进行一次测量并记录硬件与结果。不能把数据库本机测试数字直接当作用户端延迟。首页在移动网络下应优先显示文字内容，图片使用缩略图、明确尺寸和懒加载。

首期 SPA 的 SEO/动态分享卡片限制要在上线记录中明确；如果真实目标要求爬虫直接获得正文，则把 SSR 升级列为上线前置条件。

## 7. CI 与发布门禁

前端执行锁文件安装、TypeScript 检查、Lint、重点测试和生产 build；后端执行 `cargo fmt --check`、`cargo clippy --locked -- -D warnings`、单元/集成测试与 release build。集成测试使用临时 PostgreSQL，完成后清理测试资源。

流水线构建镜像并检查迁移/OpenAPI 是否同步；生产部署由明确的发布动作触发，不能因为普通分支测试就访问生产秘密或替换线上服务。文档阶段不创建这些流水线，也不声称上述检查已经运行。

## 8. 后续演进与触发条件

| 需求出现时 | 下一步 |
| --- | --- |
| 收录、分享卡片成为核心入口 | 公开站 SSR，保留 Rust API 和后台 SPA |
| 经常改写已发布长文 | 内容修订表、独立编辑草稿、切换发布版本 |
| 中文检索效果或容量不足 | 分词、pg_trgm 或独立搜索，基于实际查询验证 |
| 多实例或媒体流量增长 | S3 兼容存储、CDN、共享限流和任务锁；重新设计私有媒体访问 |
| 需要订阅、评论或更复杂的统计 | 先定义隐私与维护边界，再加入对应数据/API/后台 |

上线前配置项：域名、服务器资源、真实公开资料、备份目的地及保留成本。选择有变化时先修改本套文档，再实施代码，避免总览、接口和数据库各自演进。
