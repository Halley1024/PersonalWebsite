# Rust 后端设计

上级文档：[开发总览](README.md)。字段和路径以 [接口契约](05-api-contract.md) 为准。

Rust 后端已按本文架构实现公开/管理 API、中间件、事务与独立 CLI。实现及本地验证见 [后端说明](../../backend/README.md) 和 [验收记录](../../backend/docs/implementation.md)；下文仍包含生产部署要求，不能把本地测试视为上线验收。

## 1. 服务组成

单个 Axum HTTP 服务运行在 Tokio，使用 SQLx 连接 PostgreSQL。依赖按职责引入：Serde 负责 JSON，UUID/时间库负责类型，tracing 负责结构化日志，密码库采用 Argon2id，OpenAPI 可由 utoipa 生成。所有版本在初始化时验证兼容并锁定。

`AppState` 共享连接池、配置、媒体存储实例和时钟抽象。请求处理器只负责参数提取和响应，业务服务负责权限后的业务规则，repository 负责参数化 SQL。公开 DTO 与后台 DTO 分开，禁止直接序列化数据库管理员或 Session 模型。

## 2. 路由与中间件

| 路由组 | 中间件与行为 |
| --- | --- |
| `/api/v1/auth/*` | Origin 检查、登录限流、no-store；写操作规则见安全文档 |
| `/api/v1/admin/*` | 必须会话；写请求必须 Origin 和 CSRF；no-store |
| `/api/v1/profile` 等公开接口 | 查询限制、响应 no-store、公开 DTO |
| `/api/v1/media/{id}` | 有条件鉴权；未公开且未登录时统一 404 |
| `/health/live`、`/health/ready` | live 只检测进程；ready 检测数据库及迁移版本 |

全局生成 request_id、记录耗时与状态码、限制请求体大小并设置超时。JSON 默认最大 1 MiB，正文最多 200,000 字符；上传路由单独放宽为 12 MiB 请求体、单文件 10 MiB。普通 API 超时初始 15 秒，上传 30 秒，按实际环境调整。

CORS 默认关闭；开发走 Vite 同源代理。只信任 Caddy 的转发头，后端端口不向公网开放。应用 panic 不返回堆栈；数据库错误记录 request_id，向客户端转换为稳定错误码。

## 3. 配置与启动

非敏感配置包括 `APP_ENV`、`BIND_ADDR=0.0.0.0:8080`、`PUBLIC_ORIGIN`、`DISPLAY_TIMEZONE=Asia/Shanghai`、`MEDIA_ROOT=/data/media`、`LOG_LEVEL`、`SESSION_IDLE_HOURS=12`、`SESSION_MAX_DAYS=7`。

数据库凭据读取 `DATABASE_URL_FILE` 指向文件；开发可允许 `DATABASE_URL`，生产必须明确提供安全来源，禁止记录完整连接串。生产要求 `PUBLIC_ORIGIN` 为 HTTPS 且完全匹配实际域名；缺失关键配置时启动失败。

计划提供以下二进制命令；实施前不可当作已存在的命令执行：

- `migrate`：以迁移账号顺序执行迁移并校验 checksum；生产部署前单独运行。
- `admin-create`：交互式安全读取密码，创建唯一管理员；已有账号则拒绝，密码不放命令行参数。
- `admin-reset-password`：受服务器操作权限保护的恢复入口，重设后撤销全部会话。
- `maintenance`：清理过期会话、检查孤立临时媒体；可选执行已确认的清理任务。

生产 Web 进程使用受限运行账号，不使用数据库超级用户；迁移命令使用单独 DDL 账号。开发模式允许启动时迁移，生产避免在每个实例启动时隐式执行 DDL。

## 4. 内容事务与并发

创建内容时由服务端生成 UUID、状态 draft、version=1；kind 和 slug 后续不可修改。一次事务写入主表、扩展表、标签和图片引用。校验分类/标签 kind 一致、媒体存在且 ready，URL 协议合法。

更新通过 `UPDATE ... WHERE id = ? AND version = ?` 或行锁后校验版本；零行更新时区分不存在与版本冲突。任何子表关系变化都必须受主表同一版本保护，成功后 version 加一。若关系保存失败，整个事务回滚。

发布或下线在事务内锁定主记录，再检查版本与状态转换。首次发布设置 `published_at=now()`，之后保持原始值；每次修改更新时间。归档只读。发布级校验包括必填正文、life 日期、可用媒体、合法分类标签。公开更新执行相同校验。

删除仅允许 draft/archived，删除正文和引用关系，不直接删媒体文件；与发布/媒体删除采取一致的锁顺序。审计写入失败时管理写事务也回滚，防止关键操作无记录。

## 5. 查询设计

列表查询只选择卡片所需字段，不加载正文。计数与数据使用一致筛选；默认无全文数据库索引时接受小规模扫描。公开详情查询在 SQL 中包含 `status='published'`，不先取数据再靠前端隐藏。

关键词仅匹配标题与摘要，`q` 最大 100 字符；作为字面子串处理，对 `%`、`_` 和转义符做 LIKE 转义，并使用绑定参数。排序、kind、状态采用枚举白名单，不能拼接用户 SQL。避免 N+1，标签与图库批量加载。

## 6. 文件上传与可见性

1. 验证管理员、CSRF、请求体大小和配额，流式写同一媒体卷的临时目录。
2. 核验文件签名，允许 JPEG/PNG/WebP；最多 40,000,000 像素且单边不超过 12,000 像素，限制解码并发、内存和耗时。
3. 解码重编码，去掉 EXIF/GPS 等元数据；生成缩略图。CPU 密集处理在受并发限制的阻塞线程中执行。
4. 使用 UUID 存储键，在同一文件系统内原子重命名；数据库插入 ready 元数据后才返回成功。
5. 数据库失败则清理已重命名文件；进程崩溃产生的未入库文件由延迟扫描报告，超过 24 小时且确认无引用后清理。

媒体行在内容引用建立、资料头像绑定和媒体删除时使用一致的行锁协议：按媒体 ID 排序锁定，检查 ready，再写引用。删除先锁媒体、复查所有引用并标记 deleting，事务提交后删文件；文件删除失败可重试，不能再创建新引用。最终删除元数据并记审计，避免引用检查与保存竞争。

读取 `/media/{id}` 时先验证 ready，再检查“已发布内容引用或公开头像引用”，否则要求管理员会话；失败统一 404。文件路径由服务端存储键解析并验证在 MEDIA_ROOT 内，拒绝路径穿越。不把媒体卷挂到 Caddy 的公开静态目录。

## 7. 错误、日志与审计

业务错误映射为 400/401/403/404/409/413/415/422/429；未处理错误为 500。公开草稿请求统一 404，不能暴露“存在但未发布”。媒体已被引用时删除返回 409。

JSON 日志只记录 request_id、路由模板、状态、耗时和必要的管理员 ID；不记录密码、Cookie、CSRF token、完整正文或秘密配置。管理操作审计记录动作、目标 ID、发生时间和结果，不存正文副本。首期审计保留 180 天，登录失败仅保留最少的限流和故障排查信息。

## 8. 任务与健康检查

单机以宿主机 systemd timer 或调度容器执行备份和维护，不依赖 HTTP 请求触发。媒体清理不在普通列表请求中运行。优雅关闭停止接收请求、等待短时间内已进入的事务、关闭连接池；Caddy 在重启窗口可能返回短暂 502，首期不承诺无停机部署。

live 不访问外部系统；ready 检查数据库连接与迁移就绪，启动时检查媒体目录可读写。健康响应只含状态，不含连接串、目录和内部版本细节。

## 9. 流量与访问控制模块

analytics 模块负责事件去重、服务器补充 IP/区域/设备、7/30 天查询和过期清理；access 模块负责规则 CRUD、版本校验及统一匹配。两者使用同一数据库与日志体系。公开 API 和 Caddy 公开页面检查调用同一规则服务；管理路径独立执行 Session/CSRF，防止管理员被规则锁死。事件字段、表结构和代理检查协议见 [11](11-analytics-and-access-control.md)。
